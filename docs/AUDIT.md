# Аудит и состояние проекта (локальное тестовое окружение)

## Что было найдено в исходном проекте
Статический фронтенд без бэкенда: товары, цены и остатки были зашиты в JavaScript; «заказы» писались только в localStorage покупателя; админки не было; корзина хранила данные в браузере; использовались inline-обработчики.

## Что сделано
Серверная архитектура: SQLite (миграции, внешние ключи, CHECK-ограничения, индексы), API, админ-API, админка `/admin/`. Единый источник данных: каталог, поиск, фильтры, витрина главной, корзина и заказы работают от одной БД.

## Безопасность — найдено и исправлено в ходе тестов
| Находка | Исправление |
|---|---|
| Ссылка кнопки баннера `//evil.example` проходила проверку (open redirect из CMS) | Регулярное выражение запрещает protocol-relative URL; тест |
| Адрес `/%00` вызывал ошибку 500 | Явная проверка нулевого байта → 404; тест |
| Гонка при повторной отправке заказа с одним ключом | Повторная проверка идемпотентности внутри `BEGIN IMMEDIATE` |
| Необработанная ошибка при чрезмерном числе query-параметров | Ограничение и безопасная обработка |
| Keep-alive мог «склеить» непрочитанное тело отклонённого запроса со следующим | HTTP/1.0 без keep-alive (за прокси это не влияет на клиентов) |

## Реализованные меры
- Пароль админа: scrypt с солью; сравнение за постоянное время; пароль не в коде/репозитории; сессии в БД по хэшу токена, TTL 8 ч, выход удаляет сессию; cookie `HttpOnly; SameSite=Strict` (+`Secure` при `LP_SECURE_COOKIES=1`).
- Все админ-маршруты проверяются на сервере; для изменяющих запросов — CSRF-токен + проверка Origin; ограничение попыток входа (8 / 15 мин на IP, 40 общих).
- Цены, остатки и суммы берутся только из БД; клиентские значения игнорируются; заказ — в транзакции `BEGIN IMMEDIATE` с проверкой и списанием остатка (тест на 8 параллельных заказов 3 единиц товара: ровно 3 успешных); снимок названия/цены/артикула в позиции заказа; идемпотентность по ключу; лимит 10 заказов/час на IP; возврат остатков при отмене.
- SQL: только параметризованные запросы; сортировка — белый список; поиск экранирует `%`/`_`.
- XSS: данные в интерфейсе выводятся экранированием (витрина) и `textContent` (админка); CSP `script-src 'self'` (без inline-скриптов и eval); проверено в браузере на payload в названии товара.
- Загрузки: формат определяется по содержимому (JPEG/PNG/WebP), SVG и «картинки с кодом» отклоняются, лимит 5 МБ и 8000×8000, обязательное перекодирование в WebP, случайные имена, пути из запроса не используются; в товар можно привязать только существующие файлы из `/uploads/`.
- Заголовки: CSP, `X-Content-Type-Options`, `X-Frame-Options`/`frame-ancestors`, `Referrer-Policy`, `Permissions-Policy`; CORS не включён; `/admin/` с `noindex`, `robots.txt` закрывает только `/admin/` и `/api/`.
- Статика отдаётся только из `public/` (проверено на traversal-вариантах); БД и `server/` недоступны по HTTP.
- ПДн: не отдаются публичным API; заказы только в админке; логи без query-строк; чекбокс согласия обязателен.

## Результаты проверок
- `tests/test_api.py` — 26 тестов, все проходят (публичное API, корзина/цены/остатки, идемпотентность, гонка, авторизация, CSRF, rate limit, загрузки, XSS-данные, traversal, заголовки).
- Браузерный прогон (Chromium, Playwright, живой сервер): 57 проверок — сценарии покупателя и администратора, лента-карусель, количество до добавления, подделка localStorage, XSS, выход из админки, ошибки сети, нарушения CSP (нет), ошибки консоли (нет).
- Адаптивность (`tests/responsive_audit.py`): 10 ширин (320…1920) × 9 страниц = 90 сочетаний — горизонтального переполнения нет, интерактивных элементов меньше 36 px на 360/390 нет; скриншоты главной (320/390/1440) и каталога (390) просмотрены вручную. Проверено только в Chromium.

## Оставшиеся риски и ограничения (честно)
1. **Нет HTTPS и HSTS в самом приложении** — настраивается на reverse proxy (nginx/Caddy); затем `LP_SECURE_COOKIES=1`, `LP_TRUST_PROXY=1`, HSTS на прокси.
2. Ограничитель запросов хранится в памяти процесса: сбрасывается при перезапуске, не общий между несколькими процессами. Для нескольких инстансов нужен общий накопитель или лимиты на прокси.
3. Один администратор, без 2FA и без интерфейса смены пароля (только CLI `--reset-admin`).
4. CSP допускает `style-src 'unsafe-inline'` (интерфейс использует инлайновые стили); скрипты — строго `'self'`.
5. **Google Fonts подгружаются с серверов Google** — передача IP стороннему сервису; рекомендуется разместить шрифты локально (особенно с учётом 152-ФЗ).
6. **SEO ограничено**: маршруты на hash (`#/product/1`), поэтому у карточек нет индексируемых URL, canonical и sitemap. Нужен серверный рендеринг/чистые URL (следующий этап).
7. **Не реализовано**: онлайн-оплата, письма/уведомления о заказах (новые заказы видны только в админке), загрузка файла спецификации (поле сейчас убрано из формы), варианты товара (размер/цвет), несколько категорий у товара, отзывы и рейтинг, пагинация в админке (лимит 500 товаров / 300 заказов), экспорт заказов.
8. Не проверялось: Safari/Firefox и реальные телефоны, экранные считыватели, управление лентой с клавиатуры вручную, нагрузочное тестирование, сканирование зависимостей (внешних пакетов нет, кроме системного Pillow — обновляйте), TLS-конфигурация.
9. **Демо-данные**: 18 товаров помечены `is_demo` (цены/остатки условные, фото нет). Заменить в админке до запуска. Баннерное фото — предоставленное вами.
10. **Юридическое**: страница «Политика обработки ПДн» пуста — текст должен предоставить владелец. Техническая проверка не подтверждает соответствие 152-ФЗ: нужны уведомление Роскомнадзора, локализация баз данных граждан РФ, согласия и политика по согласованию с юристом.

## Настройка сервера
Reverse proxy с HTTPS перед `python3 server/app.py` (слушать 127.0.0.1); запуск под отдельным пользователем без прав записи в `public/` и `server/`; `data/` — права только владельцу процесса; `LP_ADMIN_PASSWORD` задавать через окружение сервиса, не через файл в репозитории; cron: `python3 server/app.py --backup` + копирование `data/` вне сервера; ограничить размер тела запросов на прокси (≥ 8 МБ для загрузки картинок только на `/api/admin/upload`).


См. также `SECURITY.md` (краткая сводка мер). Документы согласованы по результатам последнего прогона: 26 тестов API, 57 браузерных проверок, 90 адаптивных сочетаний.
