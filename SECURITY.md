# Аудит безопасности

Дата аудита: 18.10.2026. Объём: фронтенд, сервер, API, БД, админка, загрузки, корзина и заказы. Проверялось **на локальном окружении с тестовыми данными**; рабочий сайт не затрагивался.

## 1. Исходное состояние и главные находки
Предыдущая версия была статическим фронтендом без сервера: каталог зашит в JS, корзина и «заказы» только в `localStorage`, админки нет. Следствия (критические для магазина): цену, количество и сумму мог изменить кто угодно в браузере; «заказы» никуда не уходили; персональные данные оставались в браузере покупателя. **Исправлено архитектурно** — добавлен сервер с единым источником данных (SQLite) и серверным расчётом заказа.

Дефекты, найденные собственными тестами **в новом коде** и исправленные:
| Дефект | Исправление |
|---|---|
| Ссылка кнопки баннера вида `//evil.example` проходила проверку (protocol-relative → открытый редирект из CMS) | регулярное выражение запрещает `//`; тест `test_settings_and_safe_links` |
| Адрес с нулевым байтом (`/%00`) вызывал 500 вместо 404 | проверка до обращения к файловой системе |
| Гонка при параллельной отправке одного заказа (UNIQUE-конфликт → 500) | повторная проверка ключа внутри `BEGIN IMMEDIATE` |

## 2. Что реализовано
- **Админ-доступ**: сессия в `HttpOnly; SameSite=Strict` cookie (+`Secure` при `LP_SECURE_COOKIES=1`), токен хранится в БД только как SHA-256, TTL 8 ч, выход удаляет сессию на сервере. Пароль — `scrypt` (n=2¹⁴) с солью; в коде и репозитории паролей нет. Лимит входа: 8 попыток/15 мин на IP + глобальный 40/15 мин; ответ не выдаёт существование логина. Все `/api/admin/*` проверяют сессию на **сервере**; клиентские данные не определяют права.
- **CSRF**: токен `X-CSRF-Token` + проверка `Origin` для всех изменяющих админ-запросов; API принимает только `application/json`; CORS не включён (один origin).
- **XSS**: интерфейс магазина и админки выводит данные через `esc()` / `textContent`, без `innerHTML` с сырыми данными; строгая CSP `script-src 'self'` (inline-скрипты и inline-обработчики отсутствуют); содержимое CMS — только простой текст (HTML не поддерживается, ссылки кнопок — только `#/…`, `/…`, `http(s)://`).
- **SQL**: только параметризованные запросы; сортировка — белый список; параметры фильтров валидируются по типу и диапазону.
- **Цены/количество/заказ**: сервер берёт цену и остаток из БД, игнорирует клиентские `price`/`total`; остаток проверяется и списывается в одной транзакции `BEGIN IMMEDIATE`; идемпотентность по `idem_key`; лимит 10 заказов/час на IP; в заказе хранится снимок названия/артикула/цены; корзина из `localStorage` не считается доверенной.
- **Загрузка файлов**: тип определяется по содержимому (Pillow), допускаются JPEG/PNG/WebP ≤ 5 МБ и ≤ 8000×8000; изображение **перекодируется** в WebP (метаданные и вложенные данные удаляются); имя — случайное, путь клиентом не задаётся; SVG и прочее отклоняются; раздача с `nosniff`.
- **ПДн**: публичное API не возвращает заказы; заказы доступны только админке; номер заказа не позволяет получить данные; логи не содержат query-строк и тел запросов; ПДн не передаются в URL; для заказа требуется явное согласие (чекбокс + ссылка на политику).
- **Заголовки**: CSP, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`/`frame-ancestors 'none'`, `Permissions-Policy`; `/admin/` — `X-Robots-Tag: noindex`; `robots.txt` закрывает только `/admin/` и `/api/`.
- **Файлы**: сервер раздаёт только `public/` и `uploads/` (проверка realpath); БД, исходники, `.git` недоступны (тест path traversal: 9 вариантов → 404).
- **Целостность**: FK, CHECK-ограничения, индексы; миграции через `PRAGMA user_version`; удаление категории с товарами требует переноса, товар из заказов удалить нельзя (архив); журнал действий админа; `--backup`.

## 3. Результаты тестов (локально)
- `tests/test_api.py`: **26 тестов, все пройдены** (подмена цены/суммы, перерасход остатка, дубль заказа, гонка 8 потоков за 3 шт. → ровно 3 продажи, отрицательное/нулевое/огромное количество, несуществующие id, SQL-подобные строки, обход авторизации, подделанная cookie, CSRF, чужой Origin, лимит входа, logout, XSS-строки, загрузка HTML/SVG/PHP/«GIF+PHP»/не-base64/слишком большой файл, path traversal, утечки ошибок, 413/415).
- `tests/e2e_browser.py` (Chromium): **57 проверок, 0 провалов**, включая сценарии покупателя и администратора, XSS в интерфейсе, отсутствие нарушений CSP и ошибок в консоли.
- `tests/responsive_audit.py`: 10 ширин (320…1920) × 9 страниц — **0 горизонтальных переполнений**; интерактивные элементы на 360/390 px ≥ 36 px.

## 4. Ограничения проверки и остаточные риски
- Не выполнялось: сканирование зависимостей на CVE (нет сети; зависимость одна — Pillow, следите за обновлениями), нагрузочные тесты, пентест на реальном HTTPS-стенде, ручная проверка экранными читалками, реальные телефоны, Safari/Firefox (браузерные проверки — только Chromium).
- Лимиты попыток и заказов хранятся в памяти процесса (сбрасываются при перезапуске; при нескольких процессах не общие). Для публичного production добавьте лимиты на прокси.
- SQLite рассчитан на небольшой магазин (один писатель); при росте — PostgreSQL.
- CSP содержит `style-src 'unsafe-inline'` (inline-стили в разметке и Google Fonts); скрипты — строго `'self'`.
- **Google Fonts**: браузер покупателя обращается к серверам Google (передаётся IP) — для требований о ПДн лучше разместить шрифт локально (в среде без сети сделать это не удалось; сайт работает и с запасным шрифтом).
- Один администратор, без ролей и 2FA; доступ к админке стоит дополнительно ограничить на прокси (VPN/IP).
- Секреты: `.env` и `data/` в `.gitignore`. Поиск по коду приложения и истории Git паролей/ключей/токенов ничего не нашёл; пароль администратора задаётся только окружением. В `tests/` есть **тестовые** пароли для временных БД — на рабочем сайте их использовать нельзя.

## 5. Юридические и организационные вопросы (нужны владелец/юрист)
Технически подготовлены согласие и страница политики, но **не утверждается соответствие 152-ФЗ**. Требуют подтверждения: текст политики и согласия, уведомление Роскомнадзора об обработке ПДн (если применимо), хранение/обработка ПДн российских граждан на серверах в РФ, реквизиты продавца, условия доставки/оплаты/возврата, порядок работы с юрлицами и бюджетными учреждениями (счета, документы, цены для закупок), срок хранения заказов. Демо-цены, остатки и названия **не являются реальными**.
